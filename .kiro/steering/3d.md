# 3D Direction — codewithgem Portfolio

## Core Philosophy

3D should be used where it makes the experience more memorable.

3D is NOT the default. It is a selective enhancement for specific moments that benefit from spatial depth and interactivity.

## Tools

- **Three.js** — underlying 3D engine
- **React Three Fiber** — React renderer for Three.js, preferred for integration with the React component tree

## Where 3D IS Appropriate

### Hero
The hero section is the primary candidate for a 3D experience:
- Interactive 3D environment
- Floating software-related objects
- Digital workspace
- Depth layers
- Responds subtly to the visitor (mouse, scroll)

The hero 3D should NOT become visually chaotic. Restraint is key.

### Selective Memorable Moments
Beyond the hero, 3D can be used sparingly for:
- A striking visual in The Lab section
- An interactive element that enhances a project showcase
- A background element that adds depth without demanding attention

These should be rare. One or two additional 3D moments across the entire site, maximum.

## Where 3D Should NOT Be Used

- Every section
- Navigation
- Standard content areas
- Blog posts
- Work experience timeline
- Contact form
- Anywhere it does not add clear experiential value

If the same effect can be achieved with 2D animation or CSS, prefer the simpler approach.

## Progressive Enhancement

The site must work fully without 3D:
- 3D elements are enhancements, not requirements
- If WebGL is unavailable or fails, provide a graceful fallback (static image, 2D animation, or clean empty state)
- Content is never hidden behind a 3D interaction
- The site narrative and all information remain accessible without 3D

## Mobile Considerations

On mobile and lower-powered devices:
- Reduce 3D scene complexity (fewer objects, simpler geometry, lower polygon counts)
- Reduce or disable post-processing effects
- Consider replacing 3D with a performant 2D alternative on mobile
- Respect device capabilities — detect and adapt
- Touch interaction should work naturally with any 3D elements that remain

## Performance Constraints

- Lazy load 3D scenes — do not load Three.js on routes that don't use it
- Use code splitting to keep the initial bundle lean
- Limit draw calls, texture sizes, and geometry complexity
- Use instancing for repeated objects
- Dispose of materials, geometries, and textures when scenes unmount
- Target 60fps on mid-range hardware; accept 30fps minimum
- Monitor GPU memory usage
- Prefer simple shaders over complex ones unless the visual payoff is clear

## Creative Direction for the Hero

Possible visual concepts (choose or combine based on what works):
- Floating code fragments or UI elements in a dark 3D space
- A digital workspace with depth
- Abstract geometric environment that feels like "inside a system"
- Soft particles or volumes that respond to interaction
- Layered planes creating parallax depth

The hero should communicate: technical, creative, modern, immersive.
It should NOT communicate: chaotic, noisy, gamified, or purely decorative.
