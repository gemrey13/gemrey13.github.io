# Product Vision — codewithgem Portfolio

## Core Concept

> MORE THAN JUST A DEVELOPER.

This portfolio is not a standard developer resume website. It is a premium, interactive, visually impressive personal portfolio that demonstrates Gem's ability to build software, design interfaces, create interactions, and experiment with technology.

The website itself should feel like one of Gem's projects.

## Purpose

Show visitors both:
- The developer
- The person behind the developer

The website tells a story rather than listing information.

## Desired Experience

The portfolio should feel:
- Personal
- Technical
- Creative
- Modern
- Premium
- Interactive
- Slightly experimental
- Memorable

## Target Visitor Reaction

When someone opens the portfolio:
> "This isn't just another developer portfolio."

The visitor should leave thinking:
- Gem builds serious software.
- Gem understands engineering.
- Gem cares about design.
- Gem experiments with technology.
- Gem has personality.
- Gem is more than just a developer.

## Story Arc

The entire website tells this story in order:

1. **WHO AM I?** — Hero
2. **MORE THAN JUST A DEVELOPER** — Personal storytelling
3. **WHAT HAVE I BUILT?** — Projects (case studies)
4. **WHERE HAVE I WORKED?** — Work Experience (career story)
5. **WHERE HAVE I SHOWN UP?** — Events / Communities
6. **WHAT DO I DO OUTSIDE CODE?** — Volleyball (part of "More Than Just a Developer" storytelling)
7. **WHAT AM I EXPERIMENTING WITH?** — The Lab
8. **WHAT HAVE I LEARNED?** — Blog
9. **WHAT DO I USE?** — Toolkit
10. **LET'S BUILD SOMETHING** — Contact

## Section Definitions

### Hero
- Immediately establishes who Gem is
- Messaging: GEM / SOFTWARE DEVELOPER / SYSTEM BUILDER / CREATIVE ENGINEER
- Short personal statement about building software and solving complicated problems
- Should feel immersive — respond subtly to the visitor
- Should NOT become visually chaotic

### More Than Just a Developer
- One of the most important sections
- Communicates the person behind the code through storytelling, not traditional biography
- Large typography, scroll-driven storytelling
- Volleyball is part of this section (not a separate standalone section)

### Projects
- One of the main attractions
- Large, immersive project presentations — case studies, not cards
- Each project communicates: what, why, problem, what was built, technologies, challenges

### Work Experience
- Separate from Events
- Career story rather than basic resume timeline
- Employment, freelance, roles, companies, responsibilities, contributions, technologies, growth
- Professional and structured

### Where I've Shown Up (Events)
- NOT work experience
- Events, conferences, meetups, workshops, hackathons, tech gatherings, communities
- More personal and visual than Work Experience
- Communicates: "These are some of the places and communities I've been part of."

### The Lab
- Experimental area for: experimental interfaces, animation experiments, 3D experiments, AI experiments, WebGL, creative coding, automation, prototypes
- More experimental than the rest of the portfolio
- Communicates curiosity

### Blog
- Identity: "THINGS I'VE LEARNED THE HARD WAY"
- Real experiences, not generic tutorials
- Structure should make it easy to add articles later

### Toolkit
- Technologies presented as tools used to build things
- NOT skill percentage bars
- Could be interactive (selecting a tech reveals projects using it)

### Contact
- Strong emotional and visual finish
- Heading: "HAVE SOMETHING WORTH BUILDING?"
- Supporting text: "Let's make it real."
- CTA: "START A CONVERSATION"
- Should feel like the conclusion of the entire experience

### Developer Mode
- Optional hidden/secondary experience
- When enabled, exposes technical info about the website itself
- Framework, language, router, animation, rendering, status
- Playful — should be fun, not serious
- Default experience remains clean

### Footer
- Minimal: GitHub, LinkedIn, email, social links, copyright
- One subtle interactive detail

## Personal Branding

- The portfolio should show personality through writing, interaction, humor, visual storytelling, volleyball, events, experiments, photo, developer mode, and lab
- Should NOT feel overly corporate
- The goal is for visitors to remember Gem, not just the technology stack

## Technology Stack

- React
- TypeScript
- React Router
- Motion (animation)
- Anime.js (animation)
- Coconut UI
- Three.js / React Three Fiber (3D, where appropriate)

These technologies enhance the experience rather than existing for technology's sake.

## Kiro's Role

This steering file describes product direction, not rigid implementation specs. Kiro determines:
- Best architecture
- Component structure
- Exact libraries and APIs
- Animation implementation details
- 3D implementation details
- Routing implementation
- Performance strategy
- Responsive implementation
- Dependency choices

Implementation should follow the spirit and goals of this vision while keeping the codebase maintainable and performant.

## Existing Portfolio

The existing portfolio at https://codewithgem.is-a.dev/ is the starting point. The new portfolio evolves from it — preserve useful information, projects, experience, links, and personal details. Do not discard existing content simply because the visual design is changing.
