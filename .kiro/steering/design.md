# Design Direction — codewithgem Portfolio

## Visual Identity

Think of the website as a combination of:
- Modern developer portfolio
- Digital magazine
- Interactive storytelling experience
- Creative coding project
- Premium product website

The visual language draws inspiration from the quality and polish of Apple, Linear, and Vercel — while remaining completely original. Do not copy existing portfolio trends.

## Core Visual Principles

### Dark-First Design
- Dark color scheme as the primary mode
- Restrained use of color — let typography and whitespace do the work
- Subtle depth through shadows, layering, and lighting effects

### Typography
- Strong typography is a primary design tool
- Large headlines that command attention
- Clear type hierarchy
- Readable at all sizes
- Editorial feel — think magazine layouts

### Layout
- Generous whitespace — let content breathe
- Asymmetric layouts over repetitive grids
- Editorial layouts that break the conventional grid when appropriate
- Subtle depth through layering
- Each section can have its own layout personality

### Color
- Restrained palette
- Color used with intention, not decoration
- Avoid excessive neon, gradients, or saturated palettes
- Color should draw attention to important elements

## Anti-Patterns (Avoid)

- Generic portfolio templates
- Excessive neon colors
- Excessive gradients
- Excessive glassmorphism
- Cliche cyberpunk aesthetics
- Excessive particles
- Generic skill percentage bars
- Repetitive card grids
- Unnecessary visual effects
- Simply copying existing portfolio trends

## Responsive Design

The website must work beautifully across:
- Desktop
- Laptop
- Tablet
- Mobile

Mobile is NOT simply a scaled-down desktop version. The experience adapts:
- Prioritize content on smaller screens
- Maintain strong typography at all breakpoints
- Preserve the personality of the design
- Optimize touch interaction on mobile/tablet
- Layouts should feel intentional at every viewport, not collapsed

## Accessibility

The visual experience must remain accessible:
- **Keyboard navigation** — all interactive elements reachable via keyboard
- **Focus states** — clear, visible focus indicators
- **Semantic HTML** — proper heading hierarchy, landmarks, ARIA where needed
- **Readable typography** — sufficient size, line height, and spacing
- **Sufficient contrast** — meet WCAG AA contrast ratios for text
- **Screen reader support** — meaningful alt text, aria-labels, proper structure
- **Reduced motion** — visitors who prefer reduced motion get a complete experience without animation

## Interactive Elements

- Interactive elements should feel responsive and intentional
- Hover states, click feedback, and transitions should feel polished
- Interactions reveal information or enhance storytelling
- Do not add interaction purely for novelty

## Profile Photo

The personal photo should be integrated meaningfully:
- NOT a simple circular avatar
- Possible treatments: editorial image, full-bleed, masked, subtle motion, layered composition, interactive reveal
- Should feel like part of the visual identity
- Possible locations: hero, personal introduction, "More Than Just a Developer", contact

## CV Presentation

- Clear way to VIEW CV and DOWNLOAD CV
- Easy to find without making the website feel like a resume
- Integrated naturally into the flow
